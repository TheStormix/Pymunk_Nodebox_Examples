# Лабораторна робота №6 — машинне навчання з підкріпленням

## Мета

Удосконалити стратегію робота у прикладі `8_6.py` з репозиторію
[`vkopey/Pymunk_Nodebox_Examples`](https://github.com/vkopey/Pymunk_Nodebox_Examples)
за допомогою табличного **Q-learning**.

## Вихідна програма

Симуляція містить ручного робота, автоматичного робота, позитивний об'єкт
і негативний об'єкт. Автоматичний робот отримує інформацію про об'єкти через
секторний датчик і керує напрямком руху. Оригінальна реалізація просто
накопичує винагороду в таблиці `Q` без часової різниці.

## Реалізація

Файл `8_6.py` зберігає початкову структуру графічної симуляції,
але викликає `QLearningAgent` із `rl_agent.py`. Використано чотири стани:

- `0`: об'єкти не виявлено;
- `1`: корисний об'єкт у секторі датчика;
- `2`: небажаний об'єкт у секторі датчика;
- `3`: робот наблизився до межі арени.

Дії: `0` — зберігати напрямок; `1` — змінювати напрямок.
Значення в таблиці Q оновлюються методом часової різниці:

`Q(s,a) <- Q(s,a) + alpha * (r + gamma * max(Q(s',:)) - Q(s,a))`.

Винагорода обчислюється за зміною рахунку робота між рішеннями,
за виявленням об'єктів та за наближенням до межі.
Дії обираються за правилом epsilon-greedy, де epsilon поступово
зменшується до мінімального значення. Виправлено обробку кутів
датчика біля переходу `0/2pi`.

## Перевірка алгоритму

Модуль `rl_agent.py` не потребує додаткових бібліотек і сумісний з
Python 2.7 та Python 3. Автоматичні перевірки:

```bash
python -m unittest discover -s lab06 -p 'test_*.py' -v
```

Дискретний контрольний експеримент:

```bash
python lab06/demo_q_learning.py
```

Контрольний експеримент — це **спрощена модель станів і винагород**, а не
еквівалент графічної фізичної симуляції.

## Запуск оригінальної фізичної симуляції

Графічний файл `8_6.py` орієнтований на **NodeBox for OpenGL 1.7,
Pymunk 5.7.0 і Python 2.7**, як зазначено в README початкового репозиторію.
Запускати його потрібно саме у сумісному середовищі. Наш звичайний Jupyter
із Python 3.11 використовується для тестування самого алгоритму Q-learning,
а не як заміна NodeBox.

За результатами графічної симуляції можна оцінювати зміну рахунку
робота та поведінку після навчання. У верхній частині вікна відображаються
поточна `epsilon` та кількість кроків Q-learning.
